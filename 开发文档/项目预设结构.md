采用“分层解耦 + 管道流”**的设计，避免单文件超过 300 行。针对引入 JavaScript 处理浏览器操作的思路，最佳实践是**“Python 负责流程调度与算法，纯 JS 脚本下沉到独立文件注入执行”——通过 Playwright 的 `page.evaluate()` 直接在浏览器内运行独立的 `.js` 提取脚本，比在 Python 侧高频调用 WebSocket 查找元素更稳、更快，且能直接在 DevTools Console 中单独调试。

## 2. 各核心文件夹设计边界与职责

### `engine/`：业务大脑纯度保证

- **原则**：只接收标准化数据（如 `ResumeData`），输出标准评估（`EvaluationOutput`）。
- **拆分收益**：
  - `hard_filter.py` 专门处理各种奇怪的薪资字符串正则（`"4-8K"`、`"150-200元/天"`、`"18-25K·13薪"`）和学历大小比较；
  - `semantic_ranker.py` 专门做本地 BGE 向量缓存与点积运算；
  - `llm_reviewer.py` 专门处理 Prompt 拼装和不同模型供应商的返回结果容错；
  - 任何打分规则或权重的微调，只需改对应子文件，不会破坏其它逻辑。

### `browser/js/`：纯 JS 脚本下沉与注入模式

为什么不把 DOM 抓取全写在 Python 里？ 在 Boss 直聘这种前端通过复杂 Vue 渲染的页面上，用 Python 的 `page.locator().locator()` 链式取 20 多个字段会产生数十次 CDP 进程间通信，速度慢且遇到节点重绘极易报 `ElementHandle detached`。

- **开发模式**：

  1. 在 `browser/js/parse_card_list.js` 和 `parse_resume_modal.js` 中编写原生 JS 代码，直接在网页控制台（F12 Console）测试；

  2. 测试通过后，Python 侧只需一行读取并调用：

     Python

     ```
     # level2_extractor.py
     js_code = Path("browser/js/parse_resume_modal.js").read_text(encoding="utf-8")
     raw_data = page.evaluate(js_code)
     resume = ResumeData.model_validate(raw_data)  # 直接转 Pydantic 校验
     ```

### `storage/`：轻量 SQLite 状态管理

- 避免单次脚本退出后数据丢失。
- 包含两张关键表：
  - **`candidates` 表**：记录 `candidate_key`, `name`, `score`, `routing_decision`, `status` (PENDING / APPROVED / GREETED / REJECTED)；
  - **`daily_stats` 表**：按日期（如 `2026-11-14`）记录打招呼次数，单日达到 100 触发代码层熔断。

## 3. 运行生命周期与执行流

```
[启动 main.py (CLI / Web 模式)]
     │
     ├─► 1. 加载 settings.py 与 config.json
     ├─► 2. 初始化 HybridScoringEngine (预热本地 BGE 向量模型)
     ├─► 3. cdp_connector.py 接管本地 Chrome (http://localhost:9222)
     │
     ▼ (进入自动化扫描循环)
[level1_scanner.py] ──注入 parse_card_list.js──► 获取当前可视卡片
     │
     ├─► 本地 DB 去重校验 (已处理过的跳过)
     ├─► 按钮为"继续沟通" (跳过)
     └─► hard_filter.py (Tier 0 学历/薪资硬过滤)
          │
          ▼ (符合硬条件)
[level2_extractor.py]
     │
     ├─► 模拟平滑滚动，点击卡片打开微简历弹窗
     ├─► 注入 parse_resume_modal.js 提取结构化数据
     └─► 组装生成 ResumeData 实例
          │
          ▼
[hybrid_engine.py] ──进行 Tier 1 + Tier 2 + Tier 3 混合打分
     │
     ├──► AUTO_GREET 且开启直发 ──► action_executor.py 点击"立即沟通" ──► 写入 DB (GREETED)
     ├──► PENDING_REVIEW ─────────► 写入 DB (WAITING_APPROVAL) ───────► 推送至前端看板待审
     └──► REJECT ────────────────► 写入 DB (REJECTED) ──────────────► (可选点"不合适")
```

按照此架构组织后，后续从 Phase 2（Playwright + JS 采集）过渡到 Phase 4（FastAPI + Vue 3 看板）时，模块间边界分明，代码维护与调试会非常清晰。
